# Security & Bug Audit — Sparter

**Date:** 2026-07-14
**Scope:** Full codebase — auth/sessions, authorization/IDOR, file upload/import/parsing, injection/XSS, configuration/secrets.
**Method:** Parallel multi-agent audit across five attack surfaces, each finding verified against the source before inclusion.

## Summary

Three real, exploitable issues; the rest is hardening. Foundations are solid:

- **No SQL injection** — every raw query uses parameterized Drizzle `sql` templates (`${var}` → bind params).
- **No IDOR** — every DAL query scopes by `userId` derived from the session, applied as a `WHERE` filter.
- **No R2 path traversal** — object keys are UUID-based and server-derived; the client never supplies a key.
- **No hardcoded secrets**, `.env` correctly gitignored.

The two absolute priorities are **H-1** (total auth bypass on a single misconfiguration) and **H-3** (self-service DoS).

## 🔴 HIGH

### H-1 — Staging bypass grants a full authenticated identity via a static header

**Files:** `proxy.ts:13-18`, `lib/dal/auth.ts:13-25`, `lib/logger.ts:55-61`

A request carrying `x-staging-key: <STAGING_KEY>` skips **all** route protection, and `verifySession()` returns a fabricated session (`STAGING_USER_ID ?? 'staging-user'`, plan `basic`, role `user`). This sits ahead of every check in three separate places.

Compounding problems:

- Activated by **mere presence of the env var** — not gated on `VERCEL_ENV`/`NODE_ENV`. One mis-scoped env var on Vercel Production → silent total bypass in production. The only guard is a code comment (stale — it says "Railway", but the app deploys on Vercel).
- Comparison is `===`, not `crypto.timingSafeEqual` — it is a bearer credential, so timing-attackable in principle.
- Test fixtures hardcode the literal fallback `'test-staging-key'` (`tests/import.spec.ts:10`, `tests/dashboard.spec.ts:9`). If ever reused as a real key, the bypass is guessable.

**Exploit:** if the key leaks (CI logs, shared with stakeholders, committed) or is accidentally scoped to Production, an attacker sends the header → complete read/write access to the `STAGING_USER_ID` account plus a free upgrade to `basic` feature gates.

**Fix:** gate on `process.env.VERCEL_ENV !== 'production'` in all three files, use `crypto.timingSafeEqual`, and correct the stale "Railway" comment.

### H-2 — Email pre-verification enables account pre-hijacking

**File:** `auth.ts:81-96`

Every new user is force-marked `emailVerified: true` (no email actually sent) via `databaseHooks.user.create.before`, and `requireLocalEmailVerified: false` with account linking enabled for trusted providers Google/GitHub.

**Exploit (classic pre-hijacking):** an attacker registers `victim@gmail.com` with a password before the victim signs up — the account is instantly "verified". When the real victim later signs in with Google (same address), Better Auth auto-links the OAuth identity to the attacker's pre-created record. The attacker's password now unlocks the victim's financial data.

Already tracked in project memory as a temporary workaround, but it is a live vector on any public deployment.

**Fix:** remove the `databaseHooks` override and set `requireLocalEmailVerified: true` as soon as email sending ships.

### H-3 — ReDoS via user-supplied categorization regexes

**Files:** `lib/validations/pattern.ts:34-41` (source), `lib/services/categorization-match.ts:35-38` (execution)

`normalizePatternInput()` only checks that `new RegExp(source, 'i')` compiles and that flags are `''`/`i`. There is **no complexity check, no length cap, no safe-regex/RE2, no timeout**. Any authenticated user can persist e.g. `(a+)+$` via `createPattern`.

The pattern then executes synchronously via `regex.test()`:

- `lib/services/import.ts:556` — once per distinct expense description, **inside the open `db.transaction`** (patterns × rows × 2 tests).
- `lib/services/pattern-application.ts:76,182` — retroactive apply against all uncategorized expenses.
- `lib/utils/pattern-suggestions.ts:52,113` — discovery coverage check.

**Exploit (fully self-service):** create pattern `(x+x+)+y`, upload a valid CSV with a description like `"xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"` (~40 chars, no `y`), trigger import. Catastrophic backtracking blocks the Node event loop for minutes-to-forever → **platform-wide DoS**, with the import DB transaction holding locks/connections. The `try/catch` does not help: a hang is not an exception.

**Fix:** validate patterns with a linear-time check (`safe-regex2` / `recheck`), cap pattern length (no max length currently on `CreatePatternSchema.pattern`), and/or run matching in a worker with a hard timeout, or use RE2.

## 🟠 MEDIUM

### M-1 — No security headers

`next.config.ts` has no `headers()` block; `proxy.ts` sets no response headers; no `vercel.json`. Missing: CSP, `Strict-Transport-Security`, `X-Frame-Options`/`frame-ancestors` (clickjacking the finance dashboard), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`. Vercel does not add these automatically.

**Fix:** add a `headers()` block with HSTS, `nosniff`, `frame-ancestors 'none'`, `Referrer-Policy` at minimum.

### M-2 — XLSX zip-bomb / decompression memory exhaustion

**File:** `lib/services/import-parsers.ts:146-171`

The 5 MB byte cap is enforced on the **compressed** upload only. XLSX is a ZIP; a crafted `sheet1.xml` compresses >1000:1, so a <5 MB upload inflates to multi-GB XML that `read-excel-file` materializes fully **before** the 10 000-row cap is consulted.

**Exploit:** an authenticated user uploads a ~4 MB zip-bomb `.xlsx` (valid content-type), calls analyze → server OOMs / function killed. Repeatable at will.

**Fix:** inspect the ZIP central directory for declared uncompressed sizes before parsing, or stream-parse with an inflated-bytes budget.

### M-3 — No rate limiting + R2 objects never deleted

- `grep DeleteObjectCommand` across `lib/` and `app/` → **zero hits**. Nothing ever deletes an R2 object; every import "delete" removes DB rows only, leaving the object orphaned forever.
- `app/api/files/initiate/route.ts` has no rate limit, and `contentHash` is optional (`lib/validations/import.ts:47-50`), so the duplicate check is bypassable by omitting the hash.

**Impact:** a script looping initiate→PUT (5 MB each, never confirming) permanently adds storage with no cleanup and no throttle → unbounded cost. Secondary: users' bank statements (financial PII) remain in R2 indefinitely after "deletion" — a GDPR/data-retention defect.

**Fix:** rate-limit `/api/files/initiate`; add an R2 object lifecycle/deletion path wired into the import-deletion service.

## 🟡 LOW / hardening

- **L-1 — `/api/health` unauthenticated info leak** (`app/api/health/route.ts`, `lib/services/health.ts:50-56`): exposes DB error codes, latency, and names of missing R2 env vars to anyone, and runs a live DB query per hit (load amplifier). Guard with a static token or slim the body for unauthenticated callers.
- **L-2 — R2 CORS `AllowedOrigins: ["*"]`** (`r2-cors.json:3`): mitigated (PUT-only, requires a valid presigned URL), but an intercepted presigned URL is usable from any origin. Pin to production + preview origins.
- **L-3 — `proxy.ts:38` uses `path.startsWith('/proto')`**: a future route like `/protocol` would silently skip auth. Use `'/proto/'` or an exact-segment match.
- **L-4 — `docker-compose.yml:7`**: hardcoded `POSTGRES_PASSWORD: sparter` bound to `0.0.0.0:5432` (dev only, but LAN-reachable with a known password). Bind to `127.0.0.1:5432:5432`.
- **L-5 — `role` field never enforced** (`auth.ts:73-78`): defined (`user`/`admin`) but only read for display. No exploit today; any future admin capability must add an explicit `role === 'admin'` gate.
- **L-6 — `chart.tsx:95` `dangerouslySetInnerHTML`**: standard shadcn/ui chart component with static, developer-defined config (not user input). No current risk; revisit if the config ever becomes dynamic.
- **L-7 — `auth.ts:7` `BETTER_AUTH_SECRET!`**: non-null assertion with no boot-time validation → fails late at request time if unset. Add a startup assert. No `trustedOrigins` configured — safe (Better Auth defaults to trusting `baseURL`), but Vercel preview deployments will need entries for auth to work there.

## Verified sound (no action)

- **SQL injection** — raw queries in `overview.ts`, `dashboard.ts`, `imports.ts`, `transactions.ts` all use parameterized `${var}` bind params.
- **IDOR** — every DAL function scopes by `userId` from the session; verified `getExpenseById`, `getExpenseImportContext`, `getFileForUser`, and the `app/api/files/*` route handlers.
- **R2 key derivation** — `buildUserImportObjectKey` uses `encodeURIComponent(userId)` + a server-generated UUID; the client never supplies a key. Cross-user object access is not possible.
- **SSRF** — no user-controlled URL is ever fetched; the only outbound calls are to the env-configured R2 endpoint.
- **`x-pathname` spoofing** — `proxy.ts:56-57` overwrites the client-supplied header before the RSC layout reads it.
- **Open redirect** — OAuth `callbackURL` is hardcoded to `/dashboard`; no user-controlled redirect target.
- **`/proto` gating** — `force-dynamic` + `notFound()` when `PROTOTYPES_ENABLED` unset + `robots: noindex`; correct (404 in Production).
- **CSV formula injection** — parsed values are stored and rendered in React (auto-escaped); no CSV/XLSX generated from stored data, so no injection sink today.
- **`.env` hygiene** — only `.env.example` tracked; `.gitignore` covers `.env*` and `.data/`.
- **Logger redaction** — `lib/logger.ts` redacts tokens, authorization, presigned URLs, and source tokens; no PII/passwords logged.

## Remediation priority

1. **H-1** — gate the staging bypass on `VERCEL_ENV`, timing-safe compare, fix the stale comment.
2. **H-3** — ReDoS guard on `normalizePatternInput` + matcher timeout (cheapest high-impact fix).
3. **H-2** — close the email-verification bypass when email sending lands.
4. **M-1 / M-2 / M-3** — security headers, XLSX inflated-size budget, rate limit + R2 lifecycle.
5. **L-1…L-7** — opportunistic hardening.

> Coverage note: three of six audit agents were interrupted mid-run by an API session limit; the uncovered areas (IDOR sweep, injection/XSS/monetary) were completed by hand, so coverage is intact.
