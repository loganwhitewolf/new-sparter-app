## Cross-Phase Integration (gsd-integration-checker)

**Verdict: zero blockers, zero orphaned exports, zero missing connections.** Key seams verified:

1. **Phase 77 `ledger_entry_accrual` view → Phase 80 aggregations.** The view was defined-but-unconsumed
   in 77 (`lib/db/schema.ts:837-865`); Phase 80 consumes it via `resolveLedgerRowSource('competenza')`
   (`lib/dal/dashboard-filters.ts:53-55`) — the single Lens→row-source resolver — threaded into all 10
   aggregation functions. ✓ WIRED.
2. **Phase 79 registry → Phase 78 write paths.** Registry "Chiudi"/"Realizza" actions reuse
   `CloseAmortizationDialog` and route through `closePlanTx`/`realizePlanTx`; no divergent second write
   path. ✓ WIRED (DAL↔lifecycle consistency test proves reads and writes never numerically diverge).
3. **Double-netting trap (ADR 0019 §10).** No aggregation re-nets on a `ledgerRowSource` row; grep
   confirms zero `effectiveAmount()`/`isNotSecondary()` calls in the accrual write path. ✓ SAFE.
4. **Lens preservation across navigation.** `buildDashboardTabHref` + `buildDashboardCategoriesHref` +
   `buildDashboardCategoryDetailHref` all thread `?lens=` (CR-02 fix); WR-02 e2e assertion guards the
   regression. ✓ WIRED.

E2E flows traced end-to-end without breaks: **(1)** activate amortization (row → dialog → Server Action →
`activatePlanTx` atomic detach+plan+instalments), **(2)** switch dashboard lens (LensSwitch → row-source
swap → aggregation recalc → UI), **(3)** close plan from registry (`closePlanTx` → `router.refresh()`).
