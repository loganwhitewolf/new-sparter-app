<objective>
Close the D-08 anchor-contamination gap: make the reimbursement anchor **transaction-granular**
via a new frozen join table (`reimbursement_anchor_transaction`), so a later same-merchant import
can never silently inherit a share of a past refund. This is the prerequisite the rest of Phase 75
depends on for safety (RMB-08) — the frozen-set correctness gate, proven numerically inert against
the existing N=1 regression suite, end-to-end from schema to every aggregation DAL.

**Tracer choice:** this plan's Task 1 IS the phase's tracer. Per the phase brief's either/or,
this plan chooses the D-08 frozen-set correctness gate over the "link one refund and see
net/residual on the UI" slice, because: (a) it is the one piece explicitly named a *prerequisite*
for every other Phase 75 decision (D-05, D-06, D-09, D-10 all build write paths on top of it —
building them first would mean re-touching the same CTE and re-running the same regression
gate twice); (b) it touches every layer this phase's backend actually modifies (schema ->
migration -> backfill -> netting CTE -> service write path), verified end-to-end by the SAME
real-Postgres regression harness that gates every aggregation site (`dashboard.ts`, `overview.ts`,
`transactions.ts`, `expenses.ts`, `tags.ts`); and (c) the UI slice has no independent risk of its
own once this lands — `/transactions/[id]` already renders `pairedNetAmount` today (Phase 73
shipped), so "see net/residual on the UI" is not new load-bearing surface, just a rendering of
numbers this task makes trustworthy. Task 2 is real expansion (a second call site + a new
regression class), not decoration, and both tasks are wired end-to-end with a real runnable
Postgres-backed `<verify>` — production-quality, not a prototype.

Purpose: without this, D-05's create-or-append (Plan 75-02) would let a user link N refunds to an
anchor whose Expense can silently absorb unrelated future purchases, corrupting the net.
Output: `reimbursement_anchor_transaction` table + migration + backfill; `effectiveAmount()`
repointed for Expense anchors; `createPair()` records the frozen set unconditionally; full
regression suite green; a new contamination-guard test proves the fix.
</objective>

| T-75-01 | Tampering | backfill INSERT (migration 0031) | high | mitigate | `ON CONFLICT DO NOTHING` makes the backfill idempotent/rerun-safe; scoped strictly to `expense_id IS NOT NULL` rows so it can never touch a Group anchor; regression suite (Task 1 verify) is the acceptance gate before this ships to any real DB. |
