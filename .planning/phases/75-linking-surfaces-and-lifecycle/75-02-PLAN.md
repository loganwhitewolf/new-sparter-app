<objective>
Generalize the reimbursement write path from "always create, Expense-anchor only" to
**create-or-append, either Expense or Expense-Group anchor** (D-05, D-06, RMB-07, RMB-08). This is
the backend service work the multi-select picker (Plan 75-04) and the D-10 unlink lifecycle
(Plan 75-03) both build on.

Purpose: today `createPair` unconditionally INSERTs a new `reimbursement` row and only ever
resolves the anchor via a single transaction's Expense — the second refund on the same anchor
fails with a raw 23505, and there is no write path at all for anchoring on a Group. D-05 requires
"tick several eligible inflows, link them in one action" (the dinner case); RMB-08 requires
anchoring from the Expense Group detail page.
Output: `createPairTx`/`createPair` support create-or-append and both anchor shapes;
`getEligibleCounterparts` supports multi-transaction self-exclusion and a Group's occurrence-interval
window.
</objective>
