## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client picker -> createMultiRefundAction | A tampered FormData could submit an anchor/counterpartIds combination the user does not own. |
| Delete-reimbursement confirm dialog | A destructive, multi-refund-detaching action gated behind a client confirm — the SERVER must not trust the client confirmed anything; ownership + existence checks happen in the service regardless. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-75-10 | Elevation of Privilege | createMultiRefundAction anchor/counterpartIds | high | mitigate | Every id resolves through createPairTx's existing ownership checks (transaction/expense/group all scoped to session userId) inside the shared transaction — a foreign-owned id anywhere in the batch throws and rolls back the whole submission. |
| T-75-11 | Tampering | reimbursementId in deleteReimbursementAction FormData | high | mitigate | deleteReimbursementForAnchor re-scopes its own query to `r.user_id = userId`; a foreign-owned reimbursementId resolves to "not found", never a cross-user delete. |
| T-75-12 | Information Disclosure | refund/anchor descriptions rendered in the panel | low | accept | Rendered through React (auto-escaped), same convention as TransactionPairPopover — no dangerouslySetInnerHTML anywhere in this plan's components. |
| T-75-13 | Tampering | npm/pip/cargo installs | n/a | accept | No new package installs — shadcn/ui Checkbox and existing Dialog/Select primitives already in the project. |
