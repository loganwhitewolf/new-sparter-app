## Context

**Revision note (this plan was corrected once before execution).** The first draft of this plan used
`aria-label` on the disabled `<span>` for the allocation branch. That mechanism does not work: a bare
`<span>` carries the implicit ARIA role `generic`, and the ARIA spec prohibits author-supplied naming
(`aria-label`/`aria-labelledby`) from being computed into the accessible name for that role — it would
have shipped a no-op, silently failing to fix WR-01 while looking fixed in a code review. `role="link"`
was considered as a way to make `aria-label` valid there, and explicitly rejected — it was not asked
for, and it reopens the "is `aria-disabled` semantically valid on this element" debate that locked
decision #2 declares settled. The chosen mechanism instead: **visually-hidden (`sr-only`) text nested
inside the span**, which works regardless of role because it is real text content in the DOM reading
order, not an author-name attribute subject to role-based naming prohibition. `aria-disabled="true"`
is unchanged either way.

**`sr-only` is a real, already-used convention in this project** — confirmed, not assumed: Tailwind
v4 is installed (`tailwindcss@4.3.0`, CSS-based config, no `tailwind.config.*` file) and `sr-only` is
Tailwind's built-in visually-hidden utility, already used as a plain nested
`<span className="sr-only">{text}</span>` in 15+ places in this codebase (e.g.
`components/dashboard/overview/kpi-card-reading.tsx:156` — an icon-only composition-bar legend using
exactly this pattern to keep a visual-only element accessible). This plan follows that existing
convention rather than inventing a new one.

**Copy service field (D-11).** `CategoryDirectionCopy`'s switch (`lib/services/category-direction-copy.ts`)
is exhaustive over the 3-member direction union with no default case — a new required field must carry
a meaningful, non-dead value for all three directions. Since the two branches now consume the copy
through two different mechanisms (`aria-label` string vs. sr-only text), the field is reframed as the
**suffix** describing the row's affordance — real and honest for every direction, not a `{name}`-style
template that only makes sense for one consumption path:

- `out` / `in` → `rowAccessibleSuffix: 'apri dettaglio categoria'`, consumed as
  `` aria-label={`${category.name}: ${copy.rowAccessibleSuffix}`} `` on the `<Link>` — byte-identical
  resulting string to what's hardcoded today (`category-ranking-list.tsx:111`); only the source of the
  string moves.
- `allocation` → `rowAccessibleSuffix: 'dettaglio non disponibile'`, consumed as sr-only text nested
  inside the disabled `<span>`, right after the visible `{category.name}` — giving the row an
  accessible reading of "CategoryName dettaglio non disponibile" where today there is only silence
  after the name. Register matches the file's existing plain, short strings (e.g.
  `'Nessun accantonamento'`).

Links (`role="link"` is native on `<a>`) fully support author naming, so `aria-label` was never in
question for the `out`/`in` branch — only the allocation `<span>` needed a different mechanism.

**WR-02 fix (unchanged from the first draft).** Restore the `D-13/CLIST-07` comment directly above the
`<Link>`'s `href=` expression in the non-allocation branch, in *addition to* — not instead of — the
existing CR-01 comment above the ternary. No logic changes; comment-only.

**Test query mechanism.** This project has no `@testing-library/react` or `jsdom` (confirmed: no match
for either in `package.json`; `vitest.config.ts` has no `environment` override, i.e. plain Node) — every
existing test in `tests/category-ranking-list.test.tsx` renders via `react-dom/server`'s
`renderToStaticMarkup` and asserts on the resulting HTML string. There is no accessible-name/role query
available here, so "assert the sr-only text is present and announced" is implemented as the most
precise string match this test infra supports: matching the **exact rendered element**
(`<span class="sr-only">dettaglio non disponibile</span>`), not a loose substring — this rules out a
false positive from the same words appearing elsewhere in the row.
