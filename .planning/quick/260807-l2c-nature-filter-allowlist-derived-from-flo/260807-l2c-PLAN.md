<objective>
Fix the nature filter allowlist so `?nature=savings` and `?nature=investment` stop being silently
dropped on `/transactions` and `/expenses`, and make the drift structurally impossible to
reintroduce by deriving the allowlist from the `FlowNature` union instead of hand-maintaining two
duplicated literal copies.

Purpose: `lib/validations/transactions.ts` and `lib/validations/expense.ts` each carry their own
`NATURE_ALLOWED` literal. Both still contain the three v2.0-dead codes (`operational`, `financial`,
`extraordinary` — renamed/dissolved per `lib/utils/nature-labels.ts:1-2`) and both are missing the
two live replacement codes (`savings`, `investment`). Because `parseStatus`
(`lib/utils/search-params.ts:73-80`) is a total function that silently drops any value outside its
allowlist, picking "Risparmio" or "Investimento" in the Natura filter produces a URL the app quietly
ignores — the table renders unfiltered with no error. The filter's OPTION list
(`lib/utils/cascade-options.ts`, built from `NATURE_ORDER`) is already correct; only the two
validation-layer allowlists are wrong.

Output: a single exported `NATURE_FILTER_VALUES` constant in `lib/utils/nature-labels.ts`, derived
from a `Record<FlowNature, true>` object literal so that `tsc` fails if a `FlowNature` member is
ever added or removed without updating it. Both validators import this constant and delete their
local literals. A new test file locks in the full FlowNature-plus-`unclassified` matrix as a
regression gate. No DB read, no legacy-alias layer, no change to `parseStatus` itself, no change to
`lib/validations/category.ts` (its `NatureSchema` already holds the 8 correct codes and is a
different concern — assigning a category's nature, not parsing a URL filter).
</objective>
