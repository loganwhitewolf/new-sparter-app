# Quick Task 260730-o82: Transactions direction multi-select — Context

**Gathered:** 2026-07-30
**Status:** Ready for planning

<domain>
## Task Boundary

Transactions table only: change Direzione from single-select to multi-select with an **implicit default** that excludes transfers. Expenses unchanged.

</domain>

<decisions>
## Implementation Decisions

### Default semantics (locked — A, refined)
- When URL has **no** `direction` param: effective filter = `in,out,allocation,unclassified` (exclude `transfer`).
- Do **not** write the default into the URL on first render.
- Do **not** show Direzione chips while the filter is at this implicit default (`direction` param absent).
- When the user changes Direzione in the UI: write `direction` as comma-separated allowlisted codes; chips appear (standard chip pipeline).
- If the user's selection equals the default set again → clear the URL param (back to implicit default, chips disappear).
- "Cancella tutto" clears `direction` → back to implicit default (transfers hidden, no chips).

### Cascade Natura/Categoria (locked — option 1)
- Options for nature/category are the **union** of the selected direction buckets.
- While at implicit default (or explicit default set without transfer): union of `in` + `out` + `allocation` (+ unclassified if present in map) — **no transfer** categories/natures (noise).
- When user includes `transfer` in the selection: transfer natures/categories appear in the dependent selects.
- If a previously selected nature/category becomes invalid after direction change, existing clear-on-parent-change behavior (if any) applies; do not invent new cleanup unless already present.

### Scope (locked)
- **Transactions only.** Expenses keep single-select Direzione.

### Transfer activation (locked)
- User must check Trasferimenti in the multi-select to see transfer rows.

### Claude's Discretion
- Multi-select UI: checkbox list in FilterPanel (month-multi style / simple checklist) — `multi-select` type currently renders as single Select (bug/gap); fix for direction at least.
- Whether to extract shared `parseCsvAllowlist` next to `parseMonths`.
- Exact Italian labels stay: Entrate / Uscite / Accantonamenti / Trasferimenti / Non classificato.

</decisions>
