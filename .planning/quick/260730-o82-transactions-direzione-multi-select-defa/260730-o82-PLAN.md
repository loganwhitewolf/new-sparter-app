# Quick Plan: 260730-o82 — Direction multi-select (no-transfer default)

## Goal

On **Transactions** only: Direzione becomes multi-select. Absent URL `direction` ⇒ effective `in,out,allocation,unclassified` (hide transfers) with **no chips**. User must opt in to `transfer`. Cascade nature/category unions selected directions (no transfer natures until transfer is selected). Expenses unchanged.

## Context

Locked in `260730-o82-CONTEXT.md`. Branch `gsd/quick-260730-o82-tx-direction-multi` from `origin/main`.

## Tasks

### Task 1: Parse + DAL multi-direction + default

**Files:**
- `lib/utils/search-params.ts` (optional small `parseCsvAllowlist` helper) OR keep logic in validations
- `lib/validations/transactions.ts`
- `lib/dal/transactions.ts`
- `tests/transaction-filters-direction.test.ts` (new) — pure unit tests for parse + SQL-predicate helper if extracted

**Action:**
1. Export `DEFAULT_TRANSACTION_DIRECTIONS = ['in','out','allocation','unclassified'] as const` and `TYPE_ALLOWED` from validations (or a tiny `lib/utils/transaction-directions.ts` if cleaner for client imports — client toolbar must not pull server-only). Prefer `lib/utils/transaction-directions.ts` with allowlist + default + label map for shared client/server use; validations re-export/use it.
2. `ParsedTransactionFilters.type` → `directions: string[]` (always the **effective** list after parse). Parsing:
   - Prefer `direction` CSV; fall back to legacy single `type` if `direction` absent.
   - Allowlist each token via `TYPE_ALLOWED`; drop unknown.
   - If param absent (and no legacy type) → `directions = [...DEFAULT_TRANSACTION_DIRECTIONS]`.
   - If param present but empty / all invalid → `directions = []` (match nothing).
3. `toTransactionFilters` / DAL: replace single `direction?: string` with `directions?: string[]`. Build condition:
   - If `directions` undefined/omitted → no direction filter (should not happen for transactions page after parse).
   - If `directions.length === 0` → `sql\`false\`` (or equivalent empty match).
   - Else `or( inArray(direction.code, classified), includeUnclassified ? isNull(subCategory.natureId) : undefined )` where classified = directions without `'unclassified'`.
4. Unit tests: absent → default four; `direction=transfer` → `['transfer']`; `direction=in,transfer,bogus` → `['in','transfer']`; empty → `[]`.

**Verify:** `yarn vitest run tests/transaction-filters-direction.test.ts`

**Done when:** bare `/transactions` excludes transfer rows server-side; explicit `?direction=transfer` shows only transfers.

### Task 2: Toolbar multi-select UI + chips + cascade

**Files:**
- `lib/utils/table-config.ts` — add optional `implicitDefault?: string[]` on `FilterField`
- `app/(app)/transactions/transactions.table.ts` — direction → `type: 'multi-select'`, `implicitDefault: DEFAULT_TRANSACTION_DIRECTIONS`, options populated as today via page `filterOptions`
- `components/data-table/DataTableToolbar.tsx` — real multi-select (checkboxes); cascade parent resolution for multi + `implicitDefault`; chips: one per CSV token when param present (month-multi pattern); when selection equals `implicitDefault` (same set), write `null` to clear param
- `lib/utils/cascade-options.ts` — optional pure `unionFilterOptions(map, keys: string[]): FilterOption[]` helper
- `tests/data-table-toolbar.test.tsx` and/or `tests/cascade-options.test.ts` / new small test for union + default-chip absence logic if extractable

**Action:**
1. Implement `multi-select` rendering as a checklist (not the fake single Select). Toggle updates CSV via `onChange`. Selected set when param absent = `field.implicitDefault ?? []`.
2. Chip row: for `multi-select`, emit one chip per value (like months); `onRemove` drops that token; if remaining equals `implicitDefault` (set-equal) OR remaining empty-with-implicitDefault-policy: if remaining set-equals implicitDefault → clear param; if remaining empty → clear param (back to default) **OR** leave empty — **locked:** empty selection clears param → implicit default (avoid dead empty list). Wait — user may want only transfer. Empty after removing last non-default: clearing to default would re-show in/out/… Prefer: empty CSV writes `direction=` with no tokens → parse as `[]` → no rows; chips none. Set-equal to default → `null` (implicit). Never auto-expand empty to default in URL.
3. Cascade: when resolving child `dependsOn` options, split parent CSV; if parent param absent and parent field has `implicitDefault`, use that list; union option arrays by value. Do **not** fall back to `''` all-bucket when `implicitDefault` is set (that bucket includes transfer).
4. Expenses table config untouched (still `select`).

**Verify:** `yarn vitest run tests/data-table-toolbar.test.tsx tests/cascade-options.test.ts tests/transaction-filters-direction.test.ts` (+ any new)
