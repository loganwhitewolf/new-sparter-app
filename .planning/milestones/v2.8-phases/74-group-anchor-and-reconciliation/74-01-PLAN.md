<objective>
Rewrite `effectiveAmount()` (lib/dal/transaction-pairs-sql.ts) to implement D-01/D-02's proportional
spread: when a reimbursement's linked-refund net applies to an anchor with more than one member
transaction (an Expense with multiple transactions, OR an Expense Group), each member absorbs
`refundNet × memberAmount / ΣmemberOutflow`, with the fractional-cent remainder assigned by
largest-remainder to the largest-amount member. This is ONE mechanism applied everywhere (D-02) --
it supersedes Phase 73's "earliest transaction gets the whole net" resolution, which is proven
correct only for the migrated N=1 (single-transaction-anchor) case going forward.

This is the phase's tracer: prove numerical inertness for every single-transaction-anchor scenario
first, then expand to the genuinely-new Group-anchor multi-subcategory, largest-remainder, and
division-by-zero-guard cases.

Purpose: fills the documented Phase 73 gap ("the expense_group_id branch is intentionally NOT
netted") and generalizes the Q3 earliest-transaction tie-break into the real spread mechanism
RMB-02 requires.
Output: a correct, regression-proven effectiveAmount() usable unchanged by every consumer
(dashboard.ts, overview.ts, tags.ts) with zero call-site changes.
</objective>

Rewrite `effectiveAmount()` in lib/dal/transaction-pairs-sql.ts, replacing the current two-branch
CASE (anchor-gets-everything via the earliest-transaction tie-break / everyone-else-raw) with one
uniform proportional-spread expression applied to every transaction row (D-02 -- one mechanism, no
Expense/Group special case). Build it as a single correlated scalar subquery using a `WITH` clause
(Postgres allows `WITH` inside a scalar subquery used in a SELECT list) correlated to the outer
`${transactionTable.id}` / `${transactionTable.expenseId}`:

CTE `anchor`: resolves at most one reimbursement whose anchor unit contains the outer row's
expense -- `SELECT r.id AS reimbursement_id, r.expense_id, r.expense_group_id FROM reimbursement r
WHERE r.expense_id = transaction.expense_id OR r.expense_group_id = (SELECT egm.group_id FROM
expense_group_membership egm WHERE egm.expense_id = transaction.expense_id) LIMIT 1` (at most one
row given the existing reimbursement_expenseId_unique / reimbursement_expenseGroupId_unique /
expense_group_membership_expense_unique constraints).

CTE `member_expense_ids`: the anchor's member Expense id(s) -- `SELECT COALESCE(a.expense_id,
egm2.expense_id) AS expense_id FROM anchor a LEFT JOIN expense_group_membership egm2 ON
egm2.group_id = a.expense_group_id` (yields exactly `{a.expense_id}` when the anchor is
Expense-shaped since the LEFT JOIN then matches nothing; yields every Group member's expense_id
when Group-shaped).

CTE `member_transactions`: every transaction belonging to a member expense -- `SELECT m.id,
m.amount::numeric AS amount, m.occurred_at FROM transaction m WHERE m.expense_id IN (SELECT
expense_id FROM member_expense_ids) AND NOT EXISTS (SELECT 1 FROM reimbursement_refund rr2 WHERE
rr2.transaction_id = m.id)` -- the NOT EXISTS is defense-in-depth (a member transaction can never
legitimately also be a linked refund, but guard it anyway rather than assume).

CTE `refund_total`: `SELECT COALESCE(SUM(rt.amount::numeric), 0) AS total FROM reimbursement_refund
rr INNER JOIN transaction rt ON rt.id = rr.transaction_id, anchor a WHERE rr.reimbursement_id =
a.reimbursement_id` (resolved by reimbursement id, not by expense_id directly -- this is what makes
it work for Group anchors too, generalizing the old code's `r2.expense_id = ...` filter).

CTE `member_shares`: for every row in member_transactions, `raw_share = ROUND((SELECT total FROM
refund_total) * member_transactions.amount / NULLIF((SELECT SUM(amount) FROM member_transactions),
0), 2)` -- the NULLIF on the denominator turns a zero-sum member set into SQL NULL instead of a
division error; `rn = ROW_NUMBER() OVER (ORDER BY ABS(member_transactions.amount) DESC,
member_transactions.occurred_at ASC, member_transactions.id ASC)` (rank 1 = the largest-amount
member, tied-broken by earliest occurredAt then id, reusing the exact tie-break convention already
established for the Q3 case); `residual = (SELECT total FROM refund_total) - SUM(raw_share) OVER
()`; `final_share = COALESCE(raw_share, 0) + CASE WHEN rn = 1 THEN residual ELSE 0 END` (the
COALESCE on raw_share is the zero-sum-guard fallback -- a zero-sum member set makes every member's
share exactly 0, never a crash).

Final assembly: `effectiveAmount() = ${transactionTable.amount}::numeric + COALESCE((WITH anchor
AS (...), member_expense_ids AS (...), member_transactions AS (...), refund_total AS (...),
member_shares AS (...) SELECT final_share FROM member_shares WHERE id = transaction.id), 0)` -- a
transaction that is not a member of any anchor's reimbursement resolves an empty `anchor` CTE, so
every downstream CTE is empty and the outer COALESCE falls back to 0, leaving that transaction's
own raw amount untouched (identical to today's ELSE branch, now reached structurally rather than
via a second CASE arm).

Read isNotSecondary() and its 3 callers (lib/dal/dashboard.ts, lib/dal/overview.ts,
lib/dal/tags.ts) to confirm refund exclusion depends only on `reimbursement_refund.transaction_id`
and is independent of anchor shape -- leave it completely untouched (no code change).

exactly). The earlier transaction's expected amount changes from '0.00' to '-25.00'; the later
transaction's from '-50.00' to '-25.00'. Update the test's docstring/inline comments describing
"the tie-break rule" to describe the new spread mechanism instead of the retired earliest-wins
rule. The aggregation-surface assertions further down in that same test (`expectedCombined =
toDecimal('-50.00')`) do NOT change -- the combined total across both siblings is invariant to how
the net is distributed between them; leave those lines as-is.

Re-run the file's other 4 describeIfReachable blocks (Amazon N=1 regression, empty-refund probe,

anchor-side member transaction, so the new spread formula degenerates to "the whole refund_total
on that one row," identical to today's output.
