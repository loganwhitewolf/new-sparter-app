  <name>Checkpoint: Full Rimborsi journey — sidebar, list, detail, tx-page summary, Group-anchor invisibility</name>
  <what-built>
    The dedicated Rimborsi section: a "Rimborsi" sidebar nav item; a `/reimbursements` list (search,
    status filter, sortable Titolo/Netto/Data columns, colored status badges) showing every
    Expense-anchored reimbursement; a `/reimbursements/[id]` detail page with an editable title, a
    net/residual/status header, the anchor link, and the full add/remove/delete refund panel; a
    linking badge on any paired transaction row in the transactions table; and the
    `/transactions/[id]` panel demoted to a read-only summary + "Gestisci rimborso" link once a
    reimbursement exists (still offering "Aggiungi rimborso" to bootstrap the first one).
  </what-built>
  <how-to-verify>
    Run the dev server (`yarn dev`). With a user account that has at least one existing
    reimbursement (from Phases 73-75's data, or link a new one from a transaction's outflow first if
    none exist):

    1. Confirm the sidebar shows a "Rimborsi" item (after "Spese") and it navigates to
       `/reimbursements`.
    2. On `/reimbursements`: confirm every reimbursement you expect appears (including any fully
       settled / N=1 ones — the list shows ALL, D-01); try the search box (title and anchor
       substring); try the "Stato" filter (owed/settled/surplus) and confirm it narrows correctly;
       click the Titolo/Netto/Data column headers and confirm the sort cycles and re-orders rows;
       confirm the Netto/Stato columns show a colored badge matching the state (amber "Dovuti €X",
       green "Saldato", blue "Surplus €X").
    3. Click a row's title -> lands on `/reimbursements/[id]` showing the correct anchor, refund
       list, net, and residual/status matching what you saw in the list.
    4. Click the title, edit it, save -> the new title appears immediately and also updates in the
       list when you navigate back. Clear the title to empty and save -> the page falls back to
       showing the anchor's own name, not a blank heading.
    5. Use "Aggiungi rimborso" to link an additional eligible transaction -> it appears in the refund
       list and net/residual update. Use "Scollega" on a refund -> it disappears from the list, net/
       residual update, and the refunded transaction reappears as a normal inflow in `/transactions`
       under its own original category (baseline restore, unchanged Phase 75 behavior — confirm it
       still works through the new page).
    6. Use "Elimina rimborso" -> confirms, deletes, and every refund restores baseline; you land back
       on `/reimbursements` and the row is gone.
    7. Open `/transactions/[id]` for a transaction that IS linked to a reimbursement (as anchor):
       confirm it shows the compact read-only summary (net/residual/status + refund list, no
       "Scollega"/"Aggiungi rimborso"/"Elimina rimborso" controls) and a "Gestisci rimborso" link that
       lands on the correct `/reimbursements/[id]`. Open `/transactions/[id]` for an UNLINKED outflow
       transaction: confirm "Aggiungi rimborso" still works exactly as it did before this phase
       (bootstraps a brand-new reimbursement).
    8. In `/transactions`, find a row that participates in a reimbursement and confirm its badge is
       clickable and lands on the correct `/reimbursements/[id]`.
    9. Confirm nowhere in the new UI (list, detail, any dialog/picker) can you reach or see a
       Group-anchored reimbursement or an Expense Group as a reimbursement "anchor" option — the
       Group-anchor branch stays completely invisible (RMB-08 descope, still in force).
  </how-to-verify>
  <resume-signal>Type "approved" once all 9 checks pass, or describe exactly which step failed and how.</resume-signal>
