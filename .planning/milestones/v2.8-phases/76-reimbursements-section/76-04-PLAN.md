<objective>
Split the Phase-75 `ReimbursementPanel` so `/transactions/[id]` shows a compact, read-only summary
once a reimbursement exists (D-09) — add/remove/delete become the exclusive responsibility of the
dedicated `/reimbursements/[id]` page (D-06/D-07, built in Plan 76-05) — while the SAME component,
in its default variant, keeps rendering the full management body unchanged wherever it is reused.

Purpose: "one place owns the mutating actions" (D-09) requires the tx-detail page to demote from
actor to read-only summary, without regressing the still-needed "create the first link" flow that
only the tx page can offer (no reimbursement exists yet, so there is no dedicated page to link to).

Output: `ReimbursementPanel`'s new `variant` prop and the one-line `transaction-detail-client.tsx`
call-site update.
</objective>
