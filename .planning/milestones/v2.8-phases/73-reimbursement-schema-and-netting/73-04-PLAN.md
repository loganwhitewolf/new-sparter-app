<objective>
Close the last gap in D-01 ("exactly one mechanism after this phase"): repoint the STILL-LIVE
pair-creation write path (`createPair`/`deletePairByTransactionId` in
`lib/services/transaction-pairs.ts`, and `getEligibleCounterparts`'s already-paired exclusion in
`lib/dal/transaction-pairs.ts`) so that the existing transaction-table counterpart-picker UI —
unchanged in this phase — creates reimbursements, not transaction_pair rows, when a user links a
new pair today. Without this, migrated pairs would net correctly while any BRAND NEW pair a user
creates after Phase 73 ships would silently write into a table nothing reads anymore. Then execute
Plan 73-01's checkpoint decision on `transaction_pair`'s final fate, now that every consumer in the
whole phase has been repointed, and close the phase with a full-suite regression run.

Purpose: this is not new UI (RMB-07/RMB-08 linking surfaces are Phase 75) — it is keeping an
existing, currently-shipping feature (the transaction-table pair picker) correctly wired to the
generalized model, so the gap between "Phase 73 ships" and "Phase 75 ships the new linking UI"
never produces a silently-inert pair.

precondition below only returns zero once 73-03's repointing of lib/dal/transactions.ts and
lib/services/transaction-edit.ts has landed — since 73-02 and 73-03 both sit in wave 2 with no
file overlap between them, the executor could otherwise start this plan the moment 73-02 finishes
while 73-03 is still running.

finalized per the recorded checkpoint choice; full suite green.
