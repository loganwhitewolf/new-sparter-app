## Flagged Assumptions (spec-less probe fallback)

- **CLIST-06 (unclassified edge-probe row).** The probe classifier returned `unclassified` for
  CLIST-06 (no adjacency/boundary/empty/ordering/precision shape cleanly applies to "show a
  degenerate-coverage nudge"). This plan resolves the NUMERIC half deterministically:
  `projection`/`pace` are both `null` whenever the year's pace-eligible Covered Month count is
  below 2 (D-15), never coerced. The specific UI COPY/visibility rule for "exactly 1 raw Covered
  Month" (D-14's literal wording) is NOT decided at the DAL layer — this function exposes no
  `coveredMonthCount` field of its own; the page (Plan 83-04) is expected to call
  `getCoveredMonthsInYear(year)` directly for that raw count, since it is identical across every
  category row and would be redundant on each item. Flagged for the assembly plan to resolve
  explicitly, not silently inferred from `projection === null` (which is also true at 0 raw
  Covered Months, a different state — the "no data at all" empty-year case).
- **CLIST-07 (unclassified edge-probe row).** "The row's total = the detail page's total" cannot be
  fully proven in THIS phase — the category detail page still computes on the old preset-based
  `getCategoryDetail`/`getCategoryDeviations` machinery (Phase 84 scope, ADR 0020 §7). This plan
  only guarantees the STRUCTURAL half: `amount` is literally `buildYearSeries` reduce-summed from
  the same 12-point series the row renders (D-07), so once Phase 84 rewrites the detail page onto
  the same year-scoped engine, the two totals are guaranteed to agree by construction rather than
  by a cross-page assertion this phase could write today.
