## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-84-01 | Tampering | `?months=&from=` | medium | mitigate | `parseCategoryDetailWindow` accepts only the 4 whitelisted lengths and a `YYYY-MM`-shaped `from`; any other value degrades to the whole-year default (D-01) — never reflected back unvalidated, never used to build a raw SQL fragment |
| T-84-02 | Information Disclosure | `getCategoryDetailMeta`/`getCategoryDetailYearWindow` | high | mitigate | Both call `verifySession()` and every query carries the same ownership scoping as the existing `getCategoryDetail` — a category id belonging to another user (or a private, non-system category the user doesn't own) resolves to `null`, never another user's data |
| T-84-03 | Denial of Service / Business Logic | `categoryId` route param, `?year=` | low | accept | `parsePositiveIntParam`/`resolveYear` already degrade non-numeric or out-of-range input to a safe empty state / redirect (existing, unmodified behavior) |
| T-84-04 | Tampering | Sticky-column CSS injecting attacker content | low | accept | All rendered text (amounts, month labels, category name) is React-escaped JSX text, never `dangerouslySetInnerHTML` |
