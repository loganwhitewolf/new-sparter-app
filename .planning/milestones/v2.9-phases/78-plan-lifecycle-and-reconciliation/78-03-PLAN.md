<objective>
Deliver AMORT-07 (D-04, 78-CONTEXT.md): block amount/date edits on a transaction with an OPEN
amortization plan, pointing the user to the existing "rimuovi ammortamento" (Phase 77 D-09) escape
hatch. Subcategory edits are unaffected — they never go through this function (they derive via the
linked Expense, D-13).

This plan is fully independent of 78-01/78-02 (no shared files, no functional dependency — the
guard only needs the amortization_plan.status column, already shipped in Phase 77) but is
sequenced into wave 2 rather than wave 1 alongside the tracer, per this phase's tracer-first
ordering: 78-01's close/collapse write pattern is the phase's one architecturally novel piece and
leads alone; this guard is a proven, low-risk pattern extension (v2.5 pair-guard / v2.8 D-02
precedent) that expands afterward.

Purpose: stop an amortization plan from silently desynchronizing from its source transaction —
reconciling an amount edit would require rewriting the purchase-month instalment, a past/closed
month, violating ADR 0019's "never rewrite a closed month" invariant.
Output: an extended updateTransaction() guard in lib/services/transaction-edit.ts.
</objective>
