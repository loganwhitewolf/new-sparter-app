## Copywriting Contract

All copy is **Italian** (product surfaces). Developer-facing code comments are English.

### Activation Dialog (D-01)

**Dialog title:** "Ammortizza transazione"

**Dialog description (beneath title):**
"Distribuisci il costo su più mesi. Ogni rata sarà uniforme, a partire dalla data di acquisto."
(Distribute the cost over multiple months. Each instalment will be uniform, starting from the purchase date.)

**Form label — months input:**
"Mesi"

**Form helper text (beneath input):**
"Minimo 2 mesi. Ogni rata deve essere almeno €0,01."
(Minimum 2 months. Each instalment must be at least €0.01.)

**Preview section title (above schedule table):**
"Anteprima della pianificazione"
(Planning preview)

**Preview table columns:**
- "Data" (Date, format: dd/MM/yyyy)
- "Importo" (Amount, format: €333,34 with comma decimal, no thousands separator for the display)

**Preview table example:**
```
Data        Importo
14/08/2026  €333,34
14/09/2026  €333,33
14/10/2026  €333,33
```
(First instalment carries rounding remainder; day clamped to month end if purchase is on 31st, etc.)

**Confirm button (primary, accent color):**
"Ammortizza"

**Cancel button (ghost variant):**
"Annulla"

**Validation error — N too large (more instalments than cents):**
"Impossibile: €{amount} diviso {N} mesi = €{per_instalment}. Massimo {maxMonths} mesi."
(Impossible: €{amount} divided {N} months = €{per_instalment}. Maximum {maxMonths} months.)

**Validation error — N < 2:**
"Minimo 2 mesi."
(Minimum 2 months.)

### Transaction Row / Detail Page Actions (D-01, D-08, D-09)

**Activation entry point:**
- Row action menu item (table context menu) or detail-page button: **"Ammortizza"**
- Status: Shown when eligible (D-04..D-07 guards pass)
- Status: **Hidden** when transaction is involved in a reimbursement (D-04)
- Status: **Hidden** when transaction already has an active amortization plan (D-05)
- Status: **Hidden** when transaction belongs to an Expense Group (D-06)
- Status: **Hidden** when amount is too small for 2 months (amount < 2 cents, D-07)

**Undo/remove entry point:**
- Row action menu item or detail-page button: **"Rimuovi ammortamento"** (destructive variant)
- Status: Shown **only if** an active amortization plan exists on the transaction
- Icon: `Trash2` (lucide-react)

**Guard tooltip (appears on disabled/"Ammortizza" entry point when ineligible):**

When **reimbursement-involved (D-04):**
"Non puoi ammortizzare una transazione coinvolta in un rimborso. Scollega il rimborso prima."
(You cannot amortize a transaction involved in a reimbursement. Unlink the reimbursement first.)

When **already amortized (D-05):**
"Questa transazione ha già una pianificazione attiva. Rimuovila prima di crearne una nuova."
(This transaction already has an active plan. Remove it first before creating a new one.)

When **in Expense Group (D-06):**
"Non puoi ammortizzare una transazione che fa parte di un gruppo di spese. Rimuovila dal gruppo prima."
(You cannot amortize a transaction that is part of an Expense Group. Remove it from the group first.)

When **amount too small (D-07):**
"Importo troppo piccolo. Ammortizzare su 2 mesi richiederebbe rate di €{required_per_month}, impossibili."
(Amount too small. Amortizing over 2 months would require €{required_per_month} per instalment, impossible.)

### Undo Confirmation Dialog (D-09)

**Dialog title:** "Rimuovi ammortamento"

**Dialog description:**
"Questa azione eliminerà la pianificazione e tutte le rate associate. La transazione tornerà nella spesa condivisa per descrizione."
(This action will delete the plan and all associated instalments. The transaction will return to the shared expense by description.)

**Confirm button (destructive, red):**
"Rimuovi ammortamento"

**Cancel button (ghost):**
"Annulla"

**Success toast (after removal):**
"Ammortamento rimosso. Transazione ripristinata."
(Amortization removed. Transaction restored.)

**Error toast (if removal fails):**
"Errore nel rimuovere l'ammortamento: {error message}"
(Error removing amortization: {error message})

### Activation on Manual Entry Form (D-10)

**Checkbox label:**
"Ammortizza questa transazione"
(Amortize this transaction)

**Inline months input (appears beneath checkbox when checked):**
- Label: "Mesi"
- Placeholder: "2–{maxMonths}"
- Validation: Same as dialog (min 2, max based on amount)

**Inline preview section (appears beneath months input when N is valid):**
- Same table structure as activation dialog
- Compact format (smaller font, tighter spacing)

**Form-level submit button (primary, accent):**
"Crea e ammortizza" (if amortization checkbox is checked)
or
"Crea transazione" (if checkbox is unchecked)

**Success toast (after manual entry + amortization):**
"Transazione creata e ammortizzata su {N} mesi."
(Transaction created and amortized over {N} months.)

**Pre-populated from:** 
- Row action patterns from v2.8 reimbursement UI (detach action uses same pattern)
- Dialog copy mirrors existing pattern: describe action, show preview, confirm/cancel
- Guard tooltips follow v2.5 pair-guard precedent
- Toast messages follow project convention (past tense for completion, error for failures)

## UI Considerations

State coverage from the post-verification UI-consideration probe (32 applicable categories across
E1 activation dialog, E2 gated entry point, E3 undo confirmation, E4 manual-entry form, E5 guard
tooltips). Resolutions below; empty-state / error-state COPY lives in `## Copywriting Contract` and
is referenced, not restated.

### Resolved truths (covered)

| Element | Category | Truth |
|---------|----------|-------|
| E1 activation dialog | empty | Opens with an empty months input (auto-focused); preview hidden until a valid N is entered |
| E1 | invalid-input | Validation copy in red beneath the input, confirm button disabled until N ≥ 2 and each instalment ≥ €0,01 (see Copywriting) |
| E1 | populated (valid preview) | Schedule table renders computed dates + amounts; rounded amounts always sum to the transaction total via remainder on the first row |
| E1 | loading | Confirm button shows spinner + disabled while the atomic plan write is in flight; no toast until response |
| **E1 / E4** | **overflow (long plan)** | **Because months has no maximum, the preview can be hundreds of rows. The preview reuses the existing infinite-scroll table pattern from `/expenses` and `/transactions` (same virtualization / lazy-render), inside a bounded max-height container — the dialog never grows unbounded.** |
| **E1 / E4** | **error (write failure)** | **Activation is a multi-write atomic op (detach + plan + instalments); on failure the dialog STAYS OPEN with the entered values preserved and an error toast appears, so the user can retry. Mirrors the undo error-toast pattern.** |
| E1 | long-text | Transaction description is page context, not shown in the fixed title "Ammortizza transazione"; long descriptions already truncate per the v2.5 detail-page design |
| E2 entry point | loading | While server-side eligibility resolves, the action follows the row/detail page's existing loading treatment; the action never flashes enabled before eligibility is known |
| E2 | ineligible-guard | Disabled + Tooltip with one specific reason each (reimbursement / already-amortized / in-group / too-small); an ineligible entry is server-gated so it never reaches a confirmable dialog (Entry Point Visibility Matrix) |
| E3 undo dialog | loading | Confirm (revert-detach) shows spinner + disabled while the atomic teardown runs |
| E3 | error | Removal failure → error toast "Errore nel rimuovere l'ammortamento…"; the source transaction/plan is left untouched (atomic) |
| E3 | populated | Confirmation dialog states the consequence (plan + instalments deleted, transaction re-attached to shared expense) before the destructive confirm |
| E4 manual-entry form | empty / invalid / populated / loading | Inherits the E1 dialog resolutions; the inline preview is the compact variant of the same table |
| E5 guard tooltips | (unclassified → reviewed) | Not a data surface — the four Italian guard messages in the Copywriting Contract are the whole content; no additional state axis applies |
| edge-case | day-clamp | Month-end clamping (31st → last day) is deterministic and non-configurable; shown in the preview, no extra affordance this phase |

### Dismissed (not applicable — reason)

| Element · Category | Reason |
|--------------------|--------|
| E1/E4 · partial | Single-field form (months); there is no partial-data state to render |
| E1/E4 · zero-one-many | N is always ≥ 2, so the schedule never has a zero/one-row state; no singular/plural variance |
| E2 · empty / populated / partial / overflow / zero-one-many / long-text | A single action affordance (menu item / button), not a data surface — these axes don't apply; its only meaningful states are shown / disabled+tooltip / loading, covered above |
| E3 · empty / partial / overflow / zero-one-many | A fixed-content confirmation dialog with no variable data list |
| E4 · overflow / long-text | Same infinite-scroll preview truth as E1; host form's own field overflow is out of this phase's scope |

## Entry Point Visibility Matrix

| Scenario | Activation Entry | Undo Entry | Note |
|----------|-----------------|-----------|------|
| Eligible outflow (no plan) | **Shown** | Hidden | User can activate |
| Active plan exists | Disabled + tooltip | **Shown** | User can remove or wait until Phase 78 (close/realize) |
| Reimbursement-involved | Disabled + tooltip | Hidden/disabled if plan exists + tooltip | Guard applies to both |
| In Expense Group | Disabled + tooltip | Hidden/disabled if plan exists + tooltip | Guard applies to both |
| Amount < €0,02 (can't split into 2 months) | Disabled + tooltip | Hidden/disabled if plan exists + tooltip | Guard applies to both |
| Inflow transaction | Hidden (entry not displayed) | Hidden | Amortization is outflows-only (D-01 decision) |
